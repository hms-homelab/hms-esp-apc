Flash hms-esp-apc

Puts firmware v__VERSION__ onto an ESP32-S3 straight from this page. Nothing to install and nothing to build — plug the board in, pick it below, and click the button.

1. Which board is it?

The two builds differ in one thing: which pin the status LED is on. Pick the wrong one and the board still works perfectly, its LED just stays dark.

2. Plug it in and flash

The DevKitC-1 has two USB-C ports. Use the one labelled UART or COM. That port is a separate chip, so it keeps working no matter what the firmware does. The other port belongs to the ESP32-S3 itself, and this firmware takes it over for the UPS a few seconds after boot.

This browser cannot talk to serial devices. Open this page in Chrome or Edge on a desktop or laptop — Safari, Firefox and every mobile browser lack the Web Serial API.

This page has to be served over HTTPS to reach a serial port.

Your browser will ask which serial port to use. Pick the one that appears when you plug the board in. Flashing takes about a minute; leave the cable alone until it says it is done.

Choose Erase device if the board is new or has run other firmware. Leave it unticked to keep an existing board's saved WiFi and MQTT settings, which live in a separate flash area and survive a reflash.

3. Get it onto WiFi

The board waits 10 seconds after flashing, then creates its own open WiFi network named APC-XXXX, where the last four characters come from its hardware address.

  1. On a phone or laptop, join the APC-XXXX network. There is no password.
  2. A setup page should open on its own. If it does not, visit http://192.168.4.1/
  3. Pick your WiFi network, enter its password and your MQTT broker address, then save.

The board restarts, joins your network, and shows up in Home Assistant by itself. Its own page then shows the live UPS readings.

4. Connect the UPS

Run a USB cable from the UPS to the board's other USB-C port — the one you did not flash through. On a single-port board, flash first, then move the cable to the UPS and power the board from elsewhere.

If something goes wrong

No port appears when I plug the board in

Usually the cable. Plenty of USB-C cables carry power only, and a board that lights up can still have no data connection. Try a different cable first, then the other USB-C port.

The port shows up, then vanishes a few seconds later

That is the firmware doing its job. On the ESP32-S3 the USB-Serial/JTAG peripheral shares pins with USB host, so when the firmware starts the host stack the serial port disappears. The 10 second boot delay exists to give you a window to start a reflash.

To get a port that stays up indefinitely, hold BOOT, tap RESET, then release BOOT. That enters download mode. Flash from this page as normal.

Flashing fails partway through

Close anything else holding the port — Arduino IDE, a serial monitor, a previous tab of this page — and try again. A failed flash cannot brick the board; the ROM bootloader is in silicon and BOOT + RESET always gets you back to download mode.

It flashed, but the LED never lights up

Almost certainly the wrong board profile. Go back to step 1, pick the other one, and flash again. Nothing else differs between the two images, so the board was working the whole time.

I would rather build it myself

Everything this page does is in the repository. See Build and flash for the ESP-IDF route, or run scripts/flash-mac.command on a Mac to build and flash in one step.
